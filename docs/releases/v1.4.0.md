# XCC Context Collector v1.4.0

Version: 1.4.0  
Release date: 2026-09-22

## Summary

v1.4.0 expands XCC from a text-context collector into a two-path local workflow:

- **Collect** builds structured AI-ready text context from supported source-like files.
- **Attachments** hands off explicitly selected original files without converting or rewriting them.

The release also adds automated sequential attachment paste, ZIP fallback, configurable global hotkeys, persistent/exportable metadata-only History, and a final UI/reliability polish pass.

## Attachments

The new Attachments page supports:

- Add Files;
- Paste Paths from AI responses;
- explicit project-root resolution;
- ordered review/removal;
- mixed/external locations;
- file count and aggregate size;
- any explicitly selected existing regular file, regardless of Collect's text-context allowlist.

### Copy Files

Publishes the ordered selection as Windows file-system clipboard objects. XCC revalidates the selection immediately before publication and does not load all file contents into memory.

### Send One-by-One

Compatibility mode for targets that accept one file per paste event.

XCC:

- snapshots the ordered selection;
- locks to one foreground window;
- prepares one file at a time;
- dispatches one Win32 `Ctrl+V` per file;
- stops if foreground focus changes;
- supports cancellation and visible progress;
- never presses Enter or submits the message;
- never automates browser/provider DOM or APIs.

Third-party acceptance/upload completion remains outside the XCC guarantee.

### Create ZIP & Copy

Creates one standard ZIP with ZIP64 support using streaming reads and transactional finalization.

- project-relative structure when a common root exists;
- deterministic safe namespaces for mixed locations;
- no absolute or `..` archive members;
- deterministic collision handling;
- source-change/stale-file checks;
- XCC-managed bundles under `%USERPROFILE%\.xcc\attachment-bundles\`;
- 7-day stale-bundle cleanup;
- original files are never moved/deleted/rewritten.

## Global hotkeys

Settings now supports configurable:

```text
Restore / Show XCC    Ctrl+Alt+X   enabled by default
Collect & Copy        Ctrl+Alt+C   disabled by default
Attachment Handoff    Ctrl+Alt+V   disabled by default
```

Enabled bindings are validated for conflicts. Failed replacement rolls back to the last known-good registration.

## Persistent Runtime History

History now survives restarts at:

```text
%USERPROFILE%\.xcc\history.json
```

The documented `xcc-runtime-history` schema v1:

- keeps the newest 200 records;
- stores collection and attachment-transfer metadata;
- supports Export JSON and Clear History;
- recovers from corrupt top-level files while preserving a backup;
- sanitizes absolute paths;
- excludes source bodies, Git diff bodies, detected secret values, attachment contents and raw failure bodies.

## UI / product polish

- Attachments, History, Settings and About use one shared progressive page-surface width contract.
- About is now a full product page with current capabilities/privacy/runtime information.
- Attachments Size header/values are centered in a compact dedicated column.
- Selected attachment rows use one left-edge accent instead of a repeated per-cell border.
- First-run defaults are aligned with the current XCC workflow, including Selected Files and 110% interface scale.
- QSS semantic token rendering is prefix-safe and no longer generates invalid colors such as `#D2A533_hover`.

## Distribution

v1.4.0 remains **portable ZIP first**. Installer/uninstall and update-availability work are not shipped in this release and are deferred.

Package:

```text
XCC-Context-Collector-v1.4.0-win64.zip
XCC-Context-Collector-v1.4.0-win64.zip.sha256
```

Windows 10/11 x64. CPython 3.13.x is required only for source/development mode.

## Privacy

v1.4.0 remains local-first:

- no account;
- no cloud upload from XCC;
- no telemetry;
- explicit user-armed sharing;
- attachment bodies are not persisted to History;
- automated Handoff does not store target-window/process identity.
