# XCC Context Collector v1.2.0

Version: 1.2.0
Release date: 2026-07-27
Release type: Context Integrity & Reliability

## Summary

XCC v1.2.0 is a reliability-focused release for AI coding workflows. It strengthens source fidelity, Git completeness, output-budget transparency, sensitive-context visibility, large-project responsiveness, packaging reproducibility, and repository release discipline.

The supported product remains the Windows PySide6 desktop application. Installer, updater, code signing, editable hotkeys, persistent history export, and advanced context profiles remain outside this release.

## Highlights

### Exact source payloads

Collected file contents are framed without trimming, compacting, normalizing, or otherwise rewriting the source payload. Repeated blank lines, trailing spaces, multiline strings, YAML block content, and final blank lines are preserved.

### Complete Git context

Git mode uses typed porcelain status data and distinguishes index and worktree state. Staged, unstaged, untracked, renamed, copied, and deleted changes are represented explicitly, with staged and unstaged diffs kept separate.

### Stable file identity

Selected files receive stable, distinguishable display paths. Duplicate basenames, nested selections, Unicode directories, cross-root paths, and different Windows drives no longer collapse into ambiguous filename-only headers.

### Transparent character budgeting

The output planner includes complete structural sections and reports what was included, omitted, summarized, or partially included. Source files and Git diffs are not silently cut in the middle.

### Context safety warnings

XCC supports `.xccignore`, optionally respects root `.gitignore` in folder/tree modes, and warns before copy when it detects sensitive filenames, private-key material, likely API tokens, credentials, or connection strings. The detector is heuristic and does not silently redact source code.

### Responsive collection

Scanning, Git inspection, file reading, warning analysis, formatting, and budgeting run outside the Qt main thread. Progress phases are visible, conflicting controls are locked, only one job can run, and cooperative cancellation does not copy partial output.

### Result health and history

Runs are classified as `SUCCESS`, `SUCCESS_WITH_WARNINGS`, `CANCELLED`, or `FAILED`. Last Run and Runtime History expose duration, output coverage, warnings, and errors while keeping file contents, Git diffs, secret values, and failure message bodies out of history.

### Reproducible Windows release engineering

The repository now uses canonical `pyproject.toml` metadata, a CPython 3.13 baseline, separated dependency groups, Windows CI, clean PyInstaller builds, executable version resources, portable ZIP validation, SHA-256 generation, and explicit Windows 10/11 release evidence.

## Supported environment

- Windows 10 or Windows 11, 64-bit
- Portable packaged application for end users
- CPython 3.13.x for supported source development and release builds

## Portable package

Release assets:

```text
XCC-Context-Collector-v1.2.0-win64.zip
XCC-Context-Collector-v1.2.0-win64.zip.sha256
```

Extract the complete `XCC Context Collector` directory and run `XCC Context Collector.exe`. Keep `_internal` and `VERSION.txt` beside the executable.

## Upgrade notes

- Existing `%USERPROFILE%\.xcc\config.json` settings remain compatible.
- Runtime history is still in-memory and is not persisted across application restarts.
- The restore hotkey remains `Ctrl+Alt+X`.
- The legacy Tkinter picker and `keyboard` listener are unsupported development compatibility tools and are not part of the packaged application.
