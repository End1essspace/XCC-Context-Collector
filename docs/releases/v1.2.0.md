# XCC Context Collector v1.2.0

Version: 1.2.0
Release date: 2026-07-30
Release type: Context Integrity & Reliability

## Summary

XCC v1.2.0 is a reliability-focused release for developers who prepare project context for AI coding assistants. It strengthens source fidelity, Git completeness, file identity, output-budget transparency, sensitive-context visibility, large-project responsiveness, Windows integration, packaging reproducibility, and public release discipline.

The supported product is the Windows PySide6 desktop application. The release keeps the four existing collection modes and upgrades the integrity of the complete collection-to-clipboard workflow.

## Highlights

### Exact source payloads

Collected file content is framed without trimming, compacting, normalizing, or otherwise rewriting the payload. Repeated blank lines, trailing spaces, multiline strings, Markdown/YAML blocks, and final blank lines are preserved.

Compact mode now applies only to XCC-generated headings, metadata, trees, and summaries.

### Complete Git context

Git mode now uses typed null-delimited porcelain data and keeps index and worktree state separate. It supports:

- staged changes;
- unstaged changes;
- untracked files;
- renames and copies;
- deleted files;
- paths containing spaces and Unicode;
- separately labelled staged and unstaged diffs.

Git command failures are surfaced instead of appearing as an empty or clean result.

### Stable file identity

Selected Files mode produces stable, distinguishable display paths. Duplicate basenames, nested selections, Unicode directories, cross-root paths, and different Windows drives no longer collapse into ambiguous filename-only headers.

### Transparent character budgeting

The output planner includes complete sections while space remains and emits an explicit `# XCC Budget Summary` when the configured limit prevents full inclusion.

The summary reports:

- character limit and usage;
- included and omitted files;
- summarized and partial files;
- Git diff, project tree, errors, and safety-warning section status;
- a bounded list of omitted paths.

Ordinary source files and Git diff sections are not silently cut in the middle.

### Context safety visibility

XCC adds `.xccignore`, root `.gitignore` integration for folder/tree modes, and heuristic warnings for:

- sensitive filenames;
- private-key material;
- likely API tokens and access keys;
- credential assignments;
- connection strings containing credentials.

The persistent **Safety confirmation** setting is enabled by default. It can suppress the modal pre-copy prompt for trusted repeated workflows without disabling detection, generated warning summaries, counters, outcomes, or metadata-only history.

Warning summaries contain paths, line numbers, and categories only. XCC does not silently redact or modify source code.

### Responsive collection pipeline

Scanning, Git inspection, file reading, safety analysis, formatting, and budgeting run outside the Qt main thread.

The GUI now provides:

- visible collection phases and processed-file counts;
- one active job at a time;
- locked conflicting controls;
- a cooperative **Cancel** action;
- no partial clipboard replacement after cancellation;
- safe tray, close, and single-instance behavior while work is active.

### Result health and runtime history

Runs are classified as:

```text
SUCCESS
SUCCESS_WITH_WARNINGS
CANCELLED
FAILED
```

Last Run and Runtime History show duration, output coverage, truncation, warnings, and errors. History is in-memory and stores metadata only; it excludes collected file contents, Git diffs, detected values, and failure-message bodies.

### Windows desktop polish

v1.2.0 includes:

- packaged application, taskbar, header, About, and tray artwork;
- PyInstaller-aware runtime resource resolution;
- Lucide sidebar icons rendered sharply at Windows DPI scaling;
- balanced primary/service navigation layout;
- aligned Settings groups;
- persistent behavior and context settings;
- native `Ctrl+Alt+X` restore hotkey;
- tray hide/restore/Quit;
- optional Windows autostart;
- single-instance restore behavior.

### Reproducible release engineering

The repository now uses:

- canonical PEP 621 project metadata;
- one source of version truth in `xcc.__version__`;
- a CPython 3.13.x baseline;
- separated runtime, development, build, and legacy dependency groups;
- Windows GitHub Actions CI;
- isolated clean-install validation;
- clean PyInstaller packaging;
- executable version resources and `VERSION.txt`;
- packaged startup smoke testing;
- portable ZIP structure validation;
- SHA-256 generation;
- deterministic workspace cleanup;
- machine-readable automated and clean-host Windows evidence gates.

## Supported environment

- Windows 10 or Windows 11, 64-bit
- Portable packaged application for end users
- CPython 3.13.x for supported source development and release builds

The packaged application does not require Python.


Verify the checksum before extraction. Keep the complete `XCC Context Collector` directory together and run `XCC Context Collector.exe`.

## Upgrade notes

- Existing `%USERPROFILE%\.xcc\config.json` settings remain compatible.
- Older config files default **Safety confirmation** to enabled.
- Runtime history remains in-memory and is not persisted across restarts.
- The restore hotkey remains fixed at `Ctrl+Alt+X`.
- The application is portable, but settings remain in the user profile.
- The legacy Tkinter picker and `keyboard` listener are unsupported development tools and are not included in the packaged product path.

## Known limitations

The following remain outside v1.2.0:

- installer and uninstall wizard;
- automatic updater;
- code signing;
- editable hotkeys;
- persistent history export;
- self-contained portable settings;
- advanced include/exclude profiles;
- automatic secret redaction.

Sensitive-context detection is heuristic and can produce false positives or miss secrets. Review generated context before sending it to an external service.
