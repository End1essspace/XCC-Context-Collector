# XCC Context Collector v1.3.0

Version: 1.3.0  
Release date: 2026-07-31

## Summary

XCC v1.3.0 completes the direct AI-to-context workflow for Selected Files and freezes the final desktop interface for release.

A file list returned by ChatGPT, Codex, Claude, or another coding assistant can now be pasted into XCC, resolved against a visible project root, reviewed, and collected without manually reopening the file picker for every item.

The release preserves the v1.2.0 guarantees for source fidelity, Git context, character budgets, safety visibility, background collection, Windows integration, and release validation.

## Highlights

### Paste Paths

Selected Files now includes **Paste Paths** and guarded `Ctrl+V`.

Accepted input includes:

- one path per line;
- Markdown bullets and numbered lists;
- quoted or backtick-wrapped paths;
- fenced code blocks inside a longer AI response.

Pasted content is treated only as data. XCC does not execute commands, expand shell expressions, interpret globs, or search the filesystem for suffix matches.

### Explicit project-root resolution

Relative paths are resolved only under a visible project root. Canonical validation rejects traversal outside that root.

Absolute files remain supported. When selected files do not share one reliable root, XCC reports `Mixed locations` instead of inventing a misleading project scope.

### Selected Files Review

Clicking the Source summary opens a transactional review dialog with:

- ordered relative paths;
- project-root or `Mixed locations` visibility;
- extended multi-selection;
- `Delete` and **Remove Selected**;
- **Clear All**;
- **Cancel** without changing the active selection;
- **Apply Changes** only after the selection actually changes.

### Final desktop interface

The supported PySide6 application now uses one coherent dark product system across:

- the application shell;
- Collect, History, Settings, and About;
- Paste Paths and Selected Files Review;
- runtime and result-state capsules;
- metrics, inputs, buttons, disabled states, and keyboard focus;
- the tray menu.

The layout is validated from the supported `920×620` minimum through normal and maximized 2K windows at 100%, 125%, and 150% Windows scaling.

The sidebar supports:

- mouse and keyboard activation;
- Up/Down navigation across all four pages;
- wheel navigation over the complete sidebar surface;
- one page change per wheel event;
- accumulated high-resolution touchpad deltas;
- bounded first/last-page behavior;
- focus transfer to the new active page, preventing stale secondary highlights.

### Result health and runtime history

Last Run and Runtime History expose:

- outcome;
- duration;
- source and output volume;
- included, omitted, summarized, and partial coverage;
- truncation;
- warnings and errors.

History remains in-memory and metadata-only. It does not store collected file contents, Git diffs, detected values, or failure-message bodies.

## Repository cleanup

The release removes the unsupported Tkinter launcher, standalone third-party `keyboard` listener, compatibility-only dependency surface, obsolete internal wrappers, and unused helper symbols. XCC now has one supported application path: `gui.py -> xcc.gui -> xcc.pipeline`.

Repository tests were also reduced to stable behavior, package, governance, and release contracts. Exact roadmap prose, implementation snippets, and styling fragments are no longer treated as product regressions when dedicated behavioral tests cover the same requirement.

Release documentation was consolidated as part of the same cleanup: the roadmap now records product-level outcomes, the current v1.3.0 procedure is canonical, the checklist no longer repeats that procedure, and v1.2.0 validation is retained under the historical release directory. Unreferenced original icon copies were removed; active packaged assets are unchanged.

## Reliability preserved

v1.3.0 keeps the existing contracts:

- source payloads and Git diffs are not trimmed, compacted, normalized, or rewritten;
- Compact mode affects only XCC-generated structural text;
- staged and unstaged Git diffs remain separate;
- rename, copy, delete, untracked, spaces, and Unicode paths remain supported;
- source files and Git diffs are not silently cut in the middle;
- cancellation never copies partial output;
- safety detection remains warning-only;
- tray, native `Ctrl+Alt+X`, autostart, config recovery, and single-instance behavior remain supported.

## Security and privacy

- XCC is local-first and has no account, cloud upload, or telemetry.
- Relative path traversal outside the selected project root is rejected.
- Safety-warning summaries contain path, line number, and category—not detected secret values.
- Disabling **Safety confirmation** disables only the modal prompt, not detection or warning metadata.
- Users remain responsible for reviewing clipboard content before sharing it with an external AI service.

## Compatibility

- Windows 10 or Windows 11, 64-bit
- CPython 3.13.x for source/development mode
- No Python installation required for the packaged application

## Package

Public release assets:

```text
XCC-Context-Collector-v1.3.0-win64.zip
XCC-Context-Collector-v1.3.0-win64.zip.sha256
```

Extract the complete `XCC Context Collector` directory and run `XCC Context Collector.exe`. Keep `_internal` and `VERSION.txt` beside the executable.

The binaries are not code-signed. Download only from the official repository and verify the SHA-256 checksum before running the archive.
