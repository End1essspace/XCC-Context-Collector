# XCC v1.2.0 Historical Validation Record

Release: `v1.2.0`  
Status: **HISTORICAL — NOT THE CURRENT RELEASE GATE**

This document preserves the validation boundary used for the v1.2.0 Context Integrity & Reliability release. Current development and release work must use [`../M15_VALIDATION.md`](../M15_VALIDATION.md).

## Release invariant used by v1.2.0

The tag was blocked until automated validation, packaged checks, clean-host Windows 10 and Windows 11 evidence, archive/checksum validation, repository synchronization, and CI all passed for one final archive SHA-256.

## Automated candidate

The v1.2.0 candidate gate covered:

- source compilation;
- canonical version consistency;
- full pytest suite;
- isolated clean-install validation;
- clean PyInstaller build;
- packaged startup and runtime-asset smoke;
- portable ZIP creation;
- SHA-256 generation;
- archive structure and version validation;
- machine-readable automated-gate output.

Canonical command:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\validate_release_candidate.ps1 -ExpectedVersion 1.2.0
```

Expected public files:

```text
XCC-Context-Collector-v1.2.0-win64.zip
XCC-Context-Collector-v1.2.0-win64.zip.sha256
```

## Product behavior matrix

The source and packaged applications were validated for:

- Selected Files, Full Folder, Git Changed Files, and Project Tree;
- exact source-payload fidelity in compact and non-compact modes;
- staged, unstaged, untracked, rename, copy, delete, spaces, and Unicode Git cases;
- stable display paths for duplicate basenames and cross-root selections;
- `.gitignore`, `.xccignore`, and built-in exclusions;
- explicit output-budget summaries without mid-file truncation;
- safety warning summaries and persistent Safety confirmation;
- responsive background collection and cooperative cancellation;
- Last Run and metadata-only Runtime History;
- tray, native `Ctrl+Alt+X`, autostart, config recovery, and single instance.

## Clean-host evidence

One complete manual record was required on Windows 10 x64 and one on Windows 11 x64. Both records had to reference the same final archive SHA-256 and confirm:

- package extraction and startup without a development environment;
- correct version and asset surfaces;
- all four collection modes;
- fidelity, Git, ignore, budget, safety, cancellation, history, tray, hotkey, autostart, config-recovery, and single-instance checks.

Evidence JSON was private release material and was not published as a GitHub Release asset.

## Final readiness

The readiness gate verified:

- canonical source version and dated changelog entry;
- required release-note markers;
- safe archive structure and matching checksum;
- automated report version, pass state, filename, and SHA-256;
- matching Windows 10/11 evidence;
- clean `main` branch synchronized with `origin/main`;
- green CI for the release commit.

## Publication verification

After publication the release was not considered complete until the public ZIP and checksum were downloaded, hashed, extracted, launched, and checked independently.

For user-facing release details, see [`v1.2.0.md`](v1.2.0.md).
